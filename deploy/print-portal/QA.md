## 上一轮表单重做

按用户反馈，将原来的长页面重做为单个打印面板。学生在同一表单选择文件、输入学号和密码，点击一次提交即可依次完成学校认证、PDF 检查与打印提交。帮助收进弹窗，任务记录有本人数据时才展示，默认折叠。

本地运行器现加载真实 `app.py` 和打印 API，使用隔离的临时数据库。删除了模拟执行端、演示用户、模拟登录和测试状态端点。未配置真实设备时提交不可用，页面如实显示“打印服务未连接”。

- 本轮 HTML 和 CSS 由 Kimi CLI 的 `kimi-code/k3` 以 `thinking.effort=max` 重做，正常完成，用户原有默认强度已恢复。
- 浏览器 14 组场景通过：可直接填写的表单、空文件校验、一次填写的认证检查提交流程、防重复点击、密码清空与浏览器存储检查、504 后同编号恢复、认证错误、密码显示与账号切换、离线与恢复、损坏及超限文件、延迟文件读取、历史账号隔离、帮助弹窗、响应式与减少动态效果。
- 真实浏览器测试对接口进行受控拦截，结束后撤除。未向学校发送凭据或真实任务。接口交互成功不代表设备已经联通。
- 打印相关 Python 回归 22 项通过，覆盖实际路由、静态源文件访问限制、任务所有权、CSRF、幂等、执行端认证和异常状态。
- 桌面与 375px 手机截图经过检查，768px 和 1024px 视口无横向溢出。手机文件操作改为独立一行，避免挤压文件名。
- 修复了原生 FileList 随 input 清空而变化的文件选择问题，文件列表在重置前先复制。
- JavaScript 语法检查及 Git 空白检查通过。主 SPA 未修改，因此本轮不需要重新编译其 JSX。
